## Project Overview

This is a **Kirby CMS v5** website for Burnaby Chinese Evangelical Free Church (BCEFC). Kirby is a flat-file PHP CMS — there is no database; content lives as `.txt`/`.md` files inside `content/`.

## Development Commands

```bash
# Install dependencies
composer install

# Start dev server (port 8000)
composer start
# Equivalent: php -S localhost:8000 kirby/router.php

# Windows alternative (port 8123)
runServer.bat
```

- Admin panel: `http://localhost:8000/panel`
- No build step, no test suite, no linter configured.

## Architecture

### Routing
Kirby uses **file-based routing**: URL segments map directly to folders in `content/`. Numeric prefixes (e.g., `2_about/`) set sort order but are stripped from the URL. All requests flow through `index.php` via `.htaccess` rewrite rules. Direct access to `content/`, `site/`, and `kirby/` folders is blocked at the server level.

### The Four Core Layers

| Directory | Role |
|-----------|------|
| `content/` | Actual page data as `.txt` files (key: value pairs) |
| `site/blueprints/` | Defines content fields and Panel UI (YAML) |
| `site/templates/` | PHP templates that render a page type |
| `site/snippets/` | Reusable template partials (header, footer, etc.) |

**Blueprint ↔ Template pairing:** A blueprint named `site/blueprints/pages/church-home.yml` pairs with `site/templates/church-home.php`. Kirby auto-matches by filename.

### Blocks System
Pages use a **blocks builder** for flexible layout. Block types are defined in `site/blueprints/blocks/` (e.g., `hero.yml`, `card-grid.yml`, `worship-times.yml`). Templates like `church-home.php` render them with `$page->blocks()->toBlocks()`.

### Multilingual Setup
Three languages: `en` (default), `zh-cn`, `zh-tw`. Configured in `site/config/config.php`. Translation strings live in `site/languages/*.php` and are referenced in templates with `t('key')`. Each content folder has language-specific `.txt` files (e.g., `home.en.txt`, `home.zh-cn.txt`).

### Page Models
`site/models/` contains PHP classes that extend Kirby's `Page` class to add custom methods (e.g., `album.php` adds a `cover()` helper). Models auto-load by matching the page template name.

### Frontend Assets
Static files in `assets/` are plain CSS/JS — no build pipeline. Key files:
- `assets/js/index.js` — priority-nav (overflow menu), mobile burger toggle
- `assets/icons/icons.svg` — SVG sprite; reference with `<use href="#icon-name">`
- `assets/css/blocks.css` — block-specific styles

## Key Conventions

- **Adding a new page type:** Create a blueprint in `site/blueprints/pages/`, a matching template in `site/templates/`, and optionally a model in `site/models/`.
- **Adding a new block type:** Create `site/blueprints/blocks/<name>.yml` and a matching snippet in `site/snippets/blocks/<name>.php`.
- **Content edits** should go through the Panel UI or directly in `content/**/*.txt` files.
- **Debug mode** is on (`'debug' => true` in `config.php`). Turn off before deploying to production.
- `media/` is git-ignored and auto-generated by Kirby (image thumbnails, etc.) — never commit it.
